# ADR0023：明确应用与连接策略收紧

日期：2026-10-30。状态：公开连接入口前的跨语言合同。

同一真实调用主体可以注册多个逻辑应用，`connection.open` 必须像现有 `grant.request` 一样携带 `applicationRef`，不能默选某个已批准应用。此前尚未实现的公开参数现固定为 applicationRef、importAlias、deviceId、publisherAppId、remoteServiceId、connectionPolicy；不接受地址、端口、凭据或自报调用主体。

请求参数上限16 KiB，其中连接策略仍受独立8 KiB限制。标识采用既有UUID、64字符小写十六进制设备指纹、应用ID和服务/alias语法；UUID规范化为小写。缺省策略值沿用既有模式规范化，不把省略字段解释成从当前授权中隐式继承。

请求中的策略只能收紧已批准import，不能扩大它：

- 总预算不增加；禁止中继的批准不能变成允许，禁止预热的批准不能开启预热。
- 请求仍允许中继时，直连等待不得小于“批准等待与请求总预算的较小值”，避免换模式或减小等待来提前中继。请求禁止中继时直接候选使用全部总预算，等待标签不产生额外中继权限。
- 请求仍预热时，预热打开和空闲预算不增加；关闭预热后这些未使用的数值不扩大工作。
- 已批准的中继字节上限或警告阈值不能取消或增大；原来不限时可以新增更小阈值。使用精确uint64比较，不经过浮点数。

模式名不单独授予权限；比较的是规范化后的实际约束。例如将模式改成fast-connect但保留较长直连等待，不会单凭标签被判为扩大权限。普通解析错误是 INVALID_REQUEST；结构正确但超出批准范围时比较返回false，实际Agent必须拒绝为权限问题，不能把它覆盖成更宽松策略后继续连接。

这个合同只验证参数和范围关系。实际执行仍须由平台取得真实调用主体、校验所选applicationRef归属和审核版本、解析精确grant、验证远端设备及服务器授权，最后交给连接调度器。通过比较不代表已经授权；未实现的预热或字节预算也仍需能力检查。实验API不因新增合同而变成正式 `connection.open`，hello也不提前声明supported。
