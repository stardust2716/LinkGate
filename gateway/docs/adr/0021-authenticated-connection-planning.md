# ADR0021：受认证候选与原始连接预算

日期：2026-10-30。状态：两端接入实验业务入口，见 [冻结证据](../verification-v0.3-connection-planner.json)。

连接预算从 Agent 接受请求时开始，覆盖存储、授权、运行时准备和实际设备握手。Java 与 .NET 调度器都接收原始单调时间，不能在候选切换时重置超时。直接候选必须返回已完成设备认证和业务附接的通道；STUN 观测、visitor 监听端口或打洞事件本身都不算就绪。

调度器在直接窗口内优先直接候选。直接候选明确失败或窗口结束后，仅当策略允许才开启中继；direct-only 将剩余总预算用于直连。认证、能力、资源、取消和时钟回退是终止结果，不走另一路径绕过。预热和中继字节上限尚未接入，因此相关声明在传输前明确拒绝，不能忽略后继续联网。

每个候选先登记原始 socket 取消句柄，再持有授权、运行时和加密通道。取消关闭部分资源；晚到成功会被回收，只交付一个结果。两端直连和中继准备各有四个有界并发位置。Windows 中已经取消但仍执行的准备工作继续占位到真正终止。调度器不转移已交付流，不重播应用写入。

Android 的直接候选先尝试已批准 IPv4 地址；具备两个明确 STUN 目标时，LAN 只占一个短子预算，然后尝试禁用 fallback 的 XTCP。每个精确授权范围可共享一个 frpc，同时持有被允许的 STCP/XTCP visitor；direct-only 不创建 STCP visitor。不同 import 或授权版本是不同范围，不为压低总实例数而跨范围复用。监听探针只表示本地准备完成，内层设备 mTLS 和服务器租约仍为必要条件。

Android 独立 UID、不同签名的消费者已通过 SDK 完成 XTCP 64 MiB 和中继 64 MiB，核对 SHA-256、FIN、单次附接、并发取消及本地/服务器撤销。所有者测试仅在 instrumentation 中读取选中 LAN/XTCP 的聚合计数，生产 Binder 不新增管理入口。本轮实际选择 XTCP；不能把它标成 LAN，也不能据此宣称物理手机或移动网络 NAT 已验收。

Windows 当前实验入口仍保留明确的 direct-only 或显式 relay 选择，接入统一预算、取消和准备并发限制。现有宿主注入的精确 relay route 保持不变；Windows 的完整动态运行时池、直接候选组合和正式 `connection.open` 尚待接入。

两端实验 `secure.connection.*` / `secure.relay.open` 的形状和既有持久结果保持兼容。调度内核支持自动选路，不等于正式 SDK、全部策略、网络代次恢复、生产服务器工具或发布版已完成。根任务继续开放。
