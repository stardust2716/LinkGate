# ADR0009：Windows 宿主声明审核与版本化状态

2026-10-29。本工作包只提供可信宿主进程内的审核状态API。该阶段没有管理RPC、批准UI、设备grant、传输或数据通道，也不增加hello能力；后续本地声明交互命令行见[ADR0011](0011-local-review-console.md)，仍不授予网络权限。宿主必须在展示真实声明并取得用户决定后调用；普通应用不能通过控制管道自批。Windows仍为每用户信任域，不隔离同用户恶意代码。

该工作包将SQLite schema 1 原子迁移为2（当前schema3见[ADR0010](0010-revocation-capacity.md)），现存manifest初始化为pending revision=1、decision version=0且无批准。旧操作结果原样保留，旧版代码拒绝schema2；不能通过降级或删审核表来恢复权限。schema2缺失/损坏审核记录失败关闭，不自动补成默认状态。Android仍使用自己的schema1，本轮不改变其数据库或消息。

审核快照包含不可变pending声明/修订号、先前批准声明/修订号、决定版本及上次决定对应的修订号，并在内部绑定状态目录和调用范围。批准/拒绝/撤销需同时匹配当前pending修订和决定版本；A→B→A也增加pending修订，不能复用旧确认。审核版本使用非负有符号64位整数，溢出拒绝修改。

批准仅保存用户确认的整份声明作为本机候选配置，不能充当逐设备/服务grant或后端授权。pending更新保留原批准配置，拒绝pending同样不撤销旧批准；需要移除原批准时必须明确撤销。撤销清空批准并增加决定版本；重新批准须取得撤销后的新快照，旧批准操作重放只能返回历史结果，不能重新生效。

宿主修改使用独立保留的管理员操作范围，与普通应用的OS身份范围分离，绑定方法、应用、两个版本、规范化声明及决定。事务同时写入决定与幂等结果，共用原有每主体/全局额度，不淘汰历史结果。schema2阶段满额会拒绝新的决定（包括撤销）；后续[ADR0010](0010-revocation-capacity.md)以schema3及预留额度解决普通日志占满阻塞撤销的问题。存储/快照等其他失败仍须明确报告。提供宿主操作查询以恢复丢回复；没有自动重试或换号。固定异常不附带数据库路径、SQL、原始manifest或底层原因。

数据库内版本可抵御并发确认、普通重启和旧操作重放，不能检测整个受保护状态被外部回滚到旧备份；可信反回滚锚、安装身份连续性、用户批准UI、活跃会话撤销和独立设备授权仍待实现。不得把这些本地记录称为AUTH-13/15或完整0.3验收。
