# ADR0028：Windows 按授权范围托管运行时

Windows 使用 Broker 产生的不可变 ConnectionRouteScope 创建运行时。应用只提交已批准的导入、设备、发布应用和服务引用，不能传入任意地址、FRP 配置或凭据。复用键包含调用方和各级授权版本；撤权、重新批准或网络代次变化会使旧 scope 失效。

已知 IPv4 入口获得有限的优先直连时间，随后可尝试 XTCP；XTCP 必须配置至少两个不同 STUN 端点，关闭自身中继回退。只有策略允许时才另建 STCP。认证失败是终止错误，不允许通过换路径绕过授权。创建、等待及拨号共用原请求的绝对时间预算。

OwnedRuntimePool 最多保留 16 个创建、运行或关闭中的对象，最多同时创建 4 个。完全相同的 scope 共享载体，各业务流独立持有租约和取消令牌；最后一个流释放后空闲 60 秒回收。创建前登记所有权，停止时能收回迟到的子进程。清理失败的对象继续占用容量，防止资源泄漏被新建掩盖。

PublisherRuntimes 从已批准声明发现发布项，定期检查本地权限和服务器准入。后台存在不等于服务可用；实际业务仍执行租约校验及内层设备 mTLS。Owner CLI 增加本地声明、访问范围及服务器 device/service/grant 管理，保存操作 UUID 后才能发起变更；未知结果查询原操作。

首次动态运行时联调曾因把身份文件的非空要求误用于运行时空日志而清理失败。修复为仅删除本次拥有的已知配置和日志文件，允许空日志，仍拒绝链接、越界路径及未知文件。失败记录保留在本地 artifacts；不得将其描述为全程无失败。

[冻结证据](../verification-v0.3-scoped-windows-runtime.json)：运行时所有权 23 项、范围路由及 Owner 工作流 130 项通过；真实源码 FRP/mTLS 的动态发布和访问使用 66 项 SDK 检查、9 条业务连接。直连、中继、自动选择各传输 64 MiB，检查精确字节、FIN、复用、独立取消、撤权及注入网络代次。此 fixture 的 SDK 消费者在宿主进程内；独立进程和安装流程由首个可安装版验收另行证明。

宿主 `serve` 提供持续运行、stop/Ctrl+C 和拥有资源回收。私有状态目录中的 bootstrap 仅包含公开引用、当前进程创建时间和镜像摘要，供已信任的启动流程使用；它不是自动发现或信任任意 Agent 的协议。同用户恶意程序隔离、自动网络观察和生产运维仍不由此证据证明。
