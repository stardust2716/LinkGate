# ADR0022：受保护的持久服务器入口

日期：2026-10-30。状态：Linux 本地入口实现，见 [原生验证](../verification-v0.3-server-host.json)。

新认证控制面和后端已经通过真实业务验证，但原先只由 fixture 创建临时身份、权限库和授权。这不能作为正式启动方式。新增 `linkgate-server request/init/serve`，生产入口只加载所有者明确准备的身份和持久状态，与 fixture 的密钥/自动授权分开。

`request` 在私有目录中本地产生P-256 PKCS8私钥和PKCS10公开CSR，重复命令不覆盖。所有者在自己的端点签发服务器CSR；服务器不接收所有者根私钥或管理设备私钥。`init` 验证同根下的初始所有者设备证书，并独占创建权限库和独立见证；`serve` 只打开已有状态，缺失见证、身份不匹配或部分初始化均不触发自动重建。

宿主暂限Linux，要求目录0700、文件0600、当前服务账户拥有、无路径符号链接和文件硬链接。祖先不能由不可信主体控制或非sticky共享可写。数据库通过受控文件打开器打开，去除普通bbolt自动CREATE行为；正常启动期间不能因删除竞态重新生成状态。见证必须在普通权限/身份备份树外独立保护。这是软件恢复见证，不能承诺一起回滚所有保护材料仍可检测。

启动只开启明确的数字IPv4控制与认证后端两个端口。控制使用真实mTLS HTTP，后端使用 `linkgate-frp/1` ALPN与逐应用scope。没有旧token回退、dashboard、公开代理或隐式STUN。上游原始日志被丢弃；普通输出只含固定就绪/错误。宿主每秒检查保护目录、文件身份/权限及证书有效期，失败则关闭监听、认证通道并释放数据库锁。

新增WSL原生验证在Linux临时目录执行权限和锁检查，实际进行所有者mTLS hello、拒绝未配对设备、拒绝原始旧FRP输入、存储变化后的停止及重启解锁。Windows上跳过Linux测试的记录不计为通过。首次CSR用例发现测试目录默认权限不符，修正fixture为0700；没有放宽实际权限要求。

派生构建改用相对模块引用，并移除临时Git提交的VCS元数据。两份独立派生目录中，未改变的frpc及fixture产物哈希一致；这不替代不同工具链、平台和完整发布供应链验收。

本入口没有部署ECS或安装systemd。远程所有者管理CLI、设备配对/轮换、备份迁移、更新签名和回滚工具继续开放；不能把可启动服务器等同完整1.0。使用方法见 [服务器入口](../../control-plane/serverhost/README.md)。
