# ADR0018：Android 服务器配置与独立 SDK 中继

日期：2026-10-30。状态：已实现，隔离模拟器验收；完整连接策略和发布验收继续开放。

## 应用接入边界

所有者通过文档选择器导入公开服务器 JSON，确认服务器证书指纹、IPv4 和独立控制/后端端口。证书必须由已确认的所有者根签发。配置原子保存在 no-backup 私有目录；启用、启动中或运行时不可替换。存在但损坏的配置会停止启动，不回退到未组合服务器授权的预览。

前台服务先建立通知，在有界后台线程完成身份加载、服务器 hello 和运行时组合。停止会推进启动代次，迟到结果关闭后才能退出，不允许停止后重新发布网关。没有服务器配置时保留原已知 IPv4 预览；有配置时，直接和中继业务都要求当前服务器租约。

API29 及以上、完整源码构建且二进制摘要验证通过的安装包才宣告实验能力 `secure.stream.relay`。故意不打包运行时的构建保留服务器授权直接访问；部分缺失或校验失败不会假装可用。普通应用仅依赖薄 SDK，不能传 FRP 配置、端口、服务器证书或设备密钥。

## 明确选择路径

`openSecureDirectAsync` 继续对应直接访问预览，要求已批准的 direct-only import。新增 `openSecureRelayAsync` 对应单独的 `secure.relay.open`；要求协商、实验开关、允许 relay 的已批准 import、精确本地 grant 和当前服务器授权。它不会把打洞成功当作业务直连，也不自动重播或回退。

操作结果原子保留 `connectionId` 和 `path`，本地 grant snapshot 和数据库 schema 保持原样。旧结果缺失 path 时按历史 direct 解释；重启关闭旧流但保留 relay 标签。客户端拒绝未经协商的活动 relay 回复，仍可查询历史已关闭 relay 结果。pending 的 path 表示选定路径，ready 才表示内层 mTLS、授权及数据通道全部就绪。

私有 visitor 由精确服务 scope 派生；每个流持有自己的子进程和回环入口。FRP login user 保持设备/应用/角色命名空间，clientID 可带规范的随机128位实例后缀，解决同应用并发实例互踢；后缀不授予权限。最多16个并发 relay 路由，整体32流/每调用方16流和4个并发 setup 的限制继续生效。当前每流一个进程，尚需池化和长稳/性能验收，不能当作成熟资源开销。

授权、运行时启动和内层握手共用总 deadline；传给内层客户端的是剩余预算。取消先关闭数据和自有路由，再异步写日志。两个独立连接、半关闭、反压和一次性描述符保持原有协议。

## 验证与计时

[独立 SDK 证据](../verification-v0.3-android-sdk-relay.json) 区分内部桥测试和独立 UID/签名消费者：后者通过公开 Binder SDK 和私有描述符传输64MiB，核对摘要、请求FIN、重复附接拒绝、两个同应用流并存及本地/服务器撤权。

一次首轮内部桥测试的“从 guest 开始等待到 EOF”超过其10秒断言。这个观测包含主机读取就绪文件前的协调耗时，无法单独解释为撤权时延，失败记录保留。后续将该时长作为观测值，真正五秒撤权门槛由主机从写入撤权 marker 到 instrumentation 完成计时，仍严格保留。两种数字不混用。

模拟器不代表物理 ARM64、移动网络、Clash、安装更新或生产签名。当前后端仍是显式库组合与测试 fixture，没有正式服务器部署命令；不能拿上游 stock frps 代替。正式 connection.open、自动策略/网络恢复、配对运维及发布矩阵继续开发。
