# ADR0015：传输后端的逐设备控制与短期租约

日期：2026-10-29。状态：实现中的选择，尚未连接运行版或部署 ECS。

完整版本继续复用固定 FRP 的打洞、中继和计数，不把旧共享注册 token 包装成新权限系统。新的服务端 authority 负责真实设备角色、批准的发布服务、精确访问 grant、版本和短期租约；应用仍只与本机 Agent 交互。FRP 的真实控制、工作、访客和 NatHole 路径均须验证该上下文，不能只修改 Login 或 PreCheck。

Android 长期设备密钥在 Keystore，不能交给独立 frpc 读取。选择让 Agent 持有标准 mTLS 控制连接，frpc 仅通过受保护、核验自有进程身份的本机字节桥接入；服务器保留实际 mTLS 设备身份并绑定 FRP 控制/工作上下文。Windows 使用保护 Named Pipe，Android 使用应用私有 Unix Socket。桥只连接用户确认的服务端，不提供任意 SOCKS 出口，也不向 SDK 交付后端凭据。旧版传输监听器与新模式分开。

服务端采用标准 Go TLS/x509，实际握手固定所有者公开根、有效设备证书及批准的公钥。发布角色与设备命名空间从握手主体产生，不信任客户端 User、代理名或 RunID 自述。访问者必须同时有精确服务 grant；空 RunID 和跨设备借用连接均拒绝。服务端维护活动中继流关闭表，两端 Agent 继续对实际数据执行设备 mTLS 和发布端本地 grant，直连与中继具有同等身份要求。

会话租约采用标准 JWS/JWT ES256，使用成熟 go-jose 库，不实现新的密码套件。租约签发者是明确固定的服务端密钥，受众是发布设备，主体是访问设备，另绑定双方代次、应用、服务、grant/服务版本、服务器代次、唯一 ID 和不超过120秒的时限。接收端用成熟库验证签名及标准声明，再校验精确范围；禁止来自 token 的远程 JWK 地址或任意算法选择。接收后转为单调截止时间，重启、控制健康过期、网络代次改变或确认撤销均不能延长旧资格。

服务端持久状态使用 bbolt 原子事务；管理入口与普通数据入口分开，保留版本比较、操作号及撤销预留额度。服务端状态与两端本地审批属于不同边界，设备配对不自动授权所有应用。新增公开消息用 Go 标准严格 JSON v2 拒绝重复/未知字段、坏编码和异常数值，大小及对象数量有硬上限。

实现顺序：先验证持久 authority、标准租约及跨语言校验，再验证真实 mTLS 控制与私有运行时桥，然后覆盖 FRP 实际路径和存量撤销，最后连接三种策略及网络恢复。正式关口仍是 [ADR0002](0002-frp-authorization-boundary.md) 和 [安全规格](../SECURITY-SPEC.md)，任何一项未覆盖都不宣布成熟安全版。源码扩展保存在 gateway 自己的构建材料中，构建时应用于固定上游副本，不修改原有运行版或共享上游 checkout。

依赖来源：[go-jose 4.1.6 安全修复](https://github.com/go-jose/go-jose/releases/tag/v4.1.6)、[bbolt 1.5.0](https://github.com/etcd-io/bbolt/releases/tag/v1.5.0)、[Go 严格 JSON v2](https://pkg.go.dev/encoding/json/v2)。依赖固定并在发布前执行漏洞核查；库选择不等于整个后端已验收。
