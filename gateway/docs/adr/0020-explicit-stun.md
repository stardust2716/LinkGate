# ADR0020：新认证运行时的显式 STUN 目标

日期：2026-10-30。状态：后端及两端配置接入，见 [冻结证据](../verification-v0.3-explicit-stun.json)。

旧0.2.3拥有既有公共STUN备用列表；新认证Agent不继承该行为。所有者明确选择最多四个唯一、规范的数字IPv4:port目标。暂不接受主机名、IPv6、fake-IP、组播、未指定/广播、链路本地或重复目标。未配置的旧文档按禁用处理，不能暗中补公共服务器。

Agent通过私有子进程环境LINKGATE_STUN_ENDPOINTS提供防御性快照。Windows从明确的IPEndPoint列表复制，Android从所有者确认的公开配置中可选stunEndpoints数组取得；业务SDK不能设置。覆盖父环境中的同名值。未配置或格式错误的Agent模式在网络访问前拒绝，不降级到stock发现；只有完全未选Agent/显式配置的stock路径保留原有行为。

发现复用一个UDP socket，对不同配置目标执行标准Binding。只有至少两个真实目标响应，才具备分类所需观测；映射相同也可以是有效的两个观测，重复配置却不是。保留之前成功结果以应对其他目标失败。不追随未配置的OTHER/CHANGED-ADDRESS，也不把响应中一个备用地址复制成第二次客户端映射。请求复用上游的事务/来源校验和三秒上限，映射地址与端口另做校验。

输出仅有固定状态及计数，不能把sufficient写成业务直连。实际路径要由受认证数据通道和应用字节证明。Windows已通过禁用回退的XTCP 64MiB及活动撤权；Android此轮只验证新配置和实际加密中继，没有声称移动网络XTCP通过。完整自动策略、物理网络与TUN适配继续开发。

Android所有者配置示例可额外加入：

```json
{"stunEndpoints":["192.0.2.20:3478","192.0.2.21:3478"]}
```

这些是文档保留地址，须替换为真实已确认目标。需要至少两个独立目标的有效观测，不能仅凭填写一个端口或控制面注册成功推断可打洞。当前不包含生产STUN/新控制服务器部署命令，不应把普通frps当作STUN服务器。
