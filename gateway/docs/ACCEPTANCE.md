# LinkGate 成熟版验收规格

文档版本：草案 1。目标产品：LinkGate 1.0；已实现基线：0.2.3。日期：2026-10-29。本文件定义后续开发的验证要求，不表示下列功能已经实现或测试已经执行。本文仅新增规格，不授权执行安装、改网、访问业务正文或操作手机画面。

产品范围与阶段见 [产品方案](PRODUCT-PLAN.md)，接口与状态语义见 [工程规格](SPEC.md)，信任模型、授权和凭据规则见 [安全规格](SECURITY-SPEC.md)。实现若与本文或接口规格不一致，应先记录差异并决定修正规格或实现，不能在测试后改变通过标准来掩盖失败。

本文件继续约束后续生产1.0。用户于2026-10-30明确要求先交付首个可安装试用版，其冻结范围和有限验收见 [试用规格](../release/release.sdd)；剩余工作保留在 [后续规格](mature-release.sdd)，本轮不重复执行完整成熟版矩阵。

## 1. 验收对象与证据等级

首个成熟版验收 Windows x64 的发布/访问角色和 Android ARM64 的访问角色、单所有者的多台受信任设备、多应用 TCP 服务，包括 HTTP(S)、WebSocket(S)，IPv4 为必需。Android 发布角色若尚未实现，不列为首版能力。受控 SDK 和透明回环端口模式分别测试；原生 UDP、系统 VPN、任意浏览器免安装 P2P、公开多租户不列为首版已支持能力。IPv6 默认为实验能力，Linux 等只有进入明确的能力清单并通过对应矩阵后才能对外声明。

证据分为配置通过、模拟协议通过、真实同机业务通过、独立应用/跨设备业务通过、跨网络通过、长时间运行通过。低级证据不能替代高级证据：进程运行不表示注册成功；STUN 有响应不表示两次有效观测；NAT 打洞历史事件不表示当前直接通道可用；直接通道可用不表示业务已有直接字节。

当前 [0.2.3 四场景记录](../tests/NETWORK-RESULTS-v0.2.3.md) 验证了单一设备对的内置测试：2,190 MiB 文件和 3,099 次 WebSocket 回显，两端业务计数与 ECS 流量对应。移动数据/Clash 关闭轮次为 90.06% 业务字节直连，其余三轮为 100%。这些历史记录保持原样，不改成泛 NAT 成功率或新的跨应用验收；内置测试来自 LinkGate 本身的 UID，也不能替代下面独立 Android 应用的验证。

## 2. 测试准备和运行规则

每个验收运行必须冻结以下条件：构建版本、源码提交、运行时摘要、API/schema 版本、设备/系统版本、应用签名标识、网关策略与预算、服务列表、网络/VPN 场景、样本大小和收集窗口。记录中只保存匿名设备/服务引用，不保存实际服务器地址、token、私钥、候选地址、SDP、业务正文或完整配对文件。

准备两个独立示例应用：不同于 LinkGate UID/签名的 Android 客户端，以及独立 Windows 客户端。示例必须通过正式 SDK/兼容入口访问独立发布端，不能让同进程测试替代真实 IPC。后端提供确定性文件、带身份的 HTTPS 请求、WSS echo、幂等写/查询和可控故障；这些 fixture 只能用于测试，不暴露任意目标代理、命令执行或真实个人文件。

手机触摸、系统设置、Clash 切换、强行停止和重启应用均由用户手动执行。agent 可在已有授权内安装、读取元数据/诊断并运行电脑/云端自有测试工具，不操作手机画面。测试前确认显示或其他业务没有被试验中断；不停止共享 ReDesk、RustDesk 或未知进程。

每例使用独立 `runId`，按准备、无业务基线、动作、稳定收尾、采证、清理顺序执行。测试过程异常终止或观察窗口缺失时标记 `incomplete`；`incomplete`、`blocked`、`not-run` 不等于 `pass`。失败报告保留，重测生成新记录并指向原记录，不覆盖旧样本。

## 3. 分阶段门槛

| 阶段 | 必须通过的最小范围 | 阻断下一阶段的条件 |
|---|---|---|
| 0.3 应用接入 | APP-01 至 APP-09；AUTH-01 至 AUTH-08、AUTH-16/17/18/21；OBS-01/02；独立 Android 和 Windows 示例；AUTH-12 后端能力分析 | 只有同 UID 内置测试、SDK 必须持有服务器秘密、未授权应用能获得受控数据连接；细粒度后端授权未实现时只能保留明确的受限开发模式 |
| 0.4 可靠连接 | 全部 NET；OBS-01 至 OBS-05；OP-01 至 OP-07；16 服务并发和 100,000 次短连接；24 小时稳定性 | 策略不可证明、仅靠历史事件宣称就绪、静默重放写请求、统计或资源随连接数量无界增长 |
| 0.5 设备管理与运维 | 全部 AUTH（覆盖 SEC）；OP-08/09；REL-01 至 REL-05；撤销/轮换/迁移与分区验证 | 设备凭据无法独立撤销、服务端没有执行授权、未知结果导致重复操作、更新链不可核验 |
| 1.0 发布 | 所有必需用例，两套独立应用，四网络场景，72 小时稳定性，完整发布/回滚演练 | 存在未处理的关键权限、数据完整性、错误恢复问题；宣称支持的平台/路径没有证据 |

阶段名表示交付门槛，不表示安全设计可以推迟：0.3 前冻结应用身份、数据入口、授权和凭据边界。开发版尚未完成的逐设备授权必须显式标为受限测试范围，不能作为生产接入发布。

## 4. 应用接入与协议验收

| ID | 操作与故障注入 | 通过标准 |
|---|---|---|
| APP-01 | 独立 Android 应用注册、用户授权、连接服务、等待就绪、收发并关闭；再由独立 Windows 应用执行 | 正式 SDK 完成全部流程，不读取/解析 FRP 配置或运行日志；状态与实际收发一致 |
| APP-02 | 初次未安装、未启动、权限待确认、远端离线、授权被拒绝 | 返回对应稳定错误/待用户状态，调用可取消；没有无限等待或自行绕过授权 |
| APP-03 | 同一应用注册多个服务；至少 16 项服务并发工作，包含相同目标端口但不同服务身份 | 服务路由与授权不串线；单项撤销/更新不错误停止其他服务；资源上限超出时明确拒绝 |
| APP-04 | 固定端口占用、自动端口分配、已分配入口失效后重建 | 不抢占未知监听，不盲信旧端口；返回正式入口/连接句柄和版本化状态；应用无需写死 18481 |
| APP-05 | HTTPS/WSS 使用正确证书/逻辑主机；再用错误 CA、主机名、过期证书和中途证书替换 | 成功路径保留 Host、SNI、Origin、Cookie/认证语义；错误验证必须失败，不关闭校验或静默改为明文 |
| APP-06 | 独立应用的 Android cleartext 策略、VPN UID 范围及后台状态分别变化 | 兼容矩阵准确解释可用/不可用状态，不把内置 raw Socket 成功当作外部应用成功；不改写用户其他代理策略 |
| APP-07 | 文件包含已知长度和摘要；持续 WSS 包含 Ping/Pong、分片、关闭与短读；并发双向传输 | 正文、摘要、消息顺序与结束状态正确；控制帧不被误报为业务内容或故障；不截断、不串流 |
| APP-08 | 稳定 `operationId` 的网关变更在响应丢失后查询；业务写请求在远端执行后人为丢弃响应 | 网关变更按 SPEC 的去重/查询语义处理；业务请求不由网关自动重放。应用可查询原事务，不能产生第二次写入 |
| APP-09 | 受控流的短读写、半关闭、取消、慢接收端与附接超时；不支持所需流语义的协议适配器 | 保持 EOF/半关闭语义与背压；每流用户态缓冲目标不超过 256 KiB，不无限缓存或静默截断；打开后 10 秒未附接则回收，第二次附接被拒；适配器不支持时明确错误 |

## 5. 连接状态、策略和网络矩阵

每例分别测试冷启动和预热后的新连接。记录 `prewarm`、`connection.open` 与业务首字节的起止；不得从业务计时中隐去前置等待再报告“连接 0 ms”。具体预算与默认值以 SPEC 为准，运行前写入记录；超时断言允许的调度误差不得大于 `max(250 ms, 所配置预算的 5%)`，超过则记录实际超支并失败或阻断，不无限延长预算。

| ID | 场景 | 通过标准 |
|---|---|---|
| NET-01 | 冷启动时 STUN 成功但对端直接会话尚未建立；再使旧直接通道失效 | 不提前返回 DirectReady；真实原生会话/探活成功才就绪。网络改变后旧历史证据不保持实时健康状态 |
| NET-02 | `fast-connect` 在可打洞和禁止 UDP 的网络分别连接 | 在其预算内进入可用直接通道或允许的中继；中继必须显示并计数；错误不得伪装成直连 |
| NET-03 | `direct-first` 下对端延迟准备，随后成功；另一次超过预算 | 在独立预热/连接预算内等待；允许回退时记录原因和时刻，禁止回退时明确失败；不通过重复循环无限延后 deadline |
| NET-04 | `direct-only` 下阻断所有直接路径，但保留中继可达；传入允许中继的旧缓存配置 | 无直接业务通道时明确失败，中继业务字节为零。策略不得静默降级；协调流量单列 |
| NET-05 | 先建立中继 TCP/WSS，再使直接通道可用，随后建立新连接 | 旧流保持/按明确策略结束，新流可直连；允许混合路径。不能宣称旧流无缝迁移或重新发送未确认业务写 |
| NET-06 | 中继限速、告警与额度阈值，测试临界值和并发超限 | 行为与冻结策略一致；只告警不能伪装硬限额。硬限制不得产生未经约定的截断、重新提交或路径绕过 |
| NET-07 | LAN、常见 NAT、嵌套/困难 NAT、UDP 完全受限，分别注入 DNS 超时/fake-IP/STUN 不足 | 正确分类为直接/中继/失败/不完整；不改造观测来伪造成功；不支持的路径明确返回能力缺失 |
| NET-08 | 手机 Wi-Fi ↔ 移动数据，Windows IPv4 地址变化、网卡拔插及 TUN 开/关 | 旧代事件不污染新代；在已声明恢复预算内恢复或明确提示用户操作；正确重选/校验出站，未授权时不改全局路由 |
| NET-09 | Windows 同时有多块可用物理网卡，用户选择、失效、切换或撤销选择 | 不随机选取；选择与 socket 原生确认一致；失效后不会继续报告错误接口为已确认 |
| NET-10 | DNS/控制连接短断、协调服务器重启、发布端重启、控制面不可达但直接业务仍存在 | 按明确状态机处理，保留允许继续的现有流、限制新授权/续期；恢复退避有上限；不能反复开连接造成风暴 |
| NET-11 | 若声明 IPv6/LAN 优先等新能力，分别构造该路径可达、不可达和更差条件 | 候选、实际选择、业务计数与文档一致；IPv4-only 测试不替代双栈，增加开关不算实现 |

跨设备必须执行四场景：同 Wi-Fi/移动数据 × 手机 Clash 开/关，电脑 TUN 保持声明状态；另做电脑 TUN 关闭的对照，用于定位出站问题。Clash 开启组记录 LinkGate 和独立业务应用各自的 UID 范围；排除 LinkGate 后的测试结果不可描述成“业务穿过 Clash 代理仍可直连”。无需为每个网络保证打洞成功，但每例必须满足其声明策略、错误和回退预算，并提供真实路径证据。

## 6. 本机安全、身份与授权验收

下列 AUTH-01 至 AUTH-21 是本文件的执行用例，分别对应 SECURITY-SPEC 中 SEC-01 至 SEC-21 的同号安全要求，不替换其需求标识；详细威胁与机制以 SECURITY-SPEC 为准。Windows 必须明确 per-user ACL/SID 不能强隔离同一用户的恶意桌面进程，Android shared UID 内也不声称逐包强隔离。

| ID | 操作 | 通过标准 |
|---|---|---|
| AUTH-01 | Windows 其他用户、远程管道客户端访问控制面 | DACL 和实际调用主体检查拒绝；当前用户许可路径正常，并明确同用户恶意进程不属于强隔离承诺 |
| AUTH-02 | 伪 Broker 占位、PID 重用、请求体伪造用户/包名/PID | SDK/Agent 校验实际 IPC 对端，用户提供的文本和 PID 不能冒充身份；持有句柄消除 PID 重用竞态 |
| AUTH-03 | 独立 Android UID 应用先未授权，后用户授予最小 grant | 未授权不能枚举/连接/管理；获得 grant 后仅对应操作成功，列表、事件和错误不泄漏其他应用信息 |
| AUTH-04 | 签名不匹配、shared UID 集合改变、卸载重装、工作资料切换 | 无效注册被拒绝或要求重新确认；签名连续更新按声明保留授权；不只看 appId 文本 |
| AUTH-05 | 普通应用自批 grant、撤销他人、导出秘密、调用 `gateway.stop` | 一律按管理边界拒绝；自己的连接关闭保持可用；重复提示有界，不持续抢占用户界面 |
| AUTH-06 | 盗用 streamRef/附接票据到另一主体或旧代，未在 10 秒内附接或重复附接 | 数据交付绑定调用主体、授权、服务、代次；无效/过期附接拒绝并回收。另验证已授权应用可主动委托已打开 FD/数据的限制说明，不能声称防止所有委托 |
| AUTH-07 | 透明回环端口被其他本机应用访问 | 明确不提供逐应用隔离；后端认证仍执行；没有意外公网/局域网监听，不借用受控模式安全标记 |
| AUTH-08 | manifest 注入任意目标、shell、文件路径、代理名或他人服务标识 | 只发布已批准的回环目标，按 schema 和权限拒绝；失败保留旧有效配置，不启动任意代理/命令 |
| AUTH-09 | 邀请过期、拒绝、取消、重复/并发消费、暴力尝试 | 至少 192 bit 邀请秘密，不超过 5 分钟；消费原子且单次，错误不泄漏其他设备，失败尝试限流 |
| AUTH-10 | 重复设备名、公钥替换、把邀请复制给错误设备 | 邀请不包含长期私钥，批准绑定真实新公钥；名称或目录静默替换不能改变信任 |
| AUTH-11 | 错误服务端证书、错误设备身份、协议降级和重放 | 认证失败必须关闭，不能回落明文或关闭验证；控制 TLS 不被当作数据面身份的独立证明 |
| AUTH-12 | 合法设备凭据请求未授权角色、服务或他人代理命名空间 | 服务端真实拒绝，不仅 UI 隐藏；后端不足以执行则回设计门槛，不发布成熟授权声明 |
| AUTH-13 | 在线撤销 grant/设备，保持一个直接流和中继流，再尝试新连接 | 权威端确认后立即拒绝新连接，5 秒内关闭对应活动会话；不能换路径使用旧授权 |
| AUTH-14 | 撤销时控制面/对端分区，数据通道仍可通信 | 租约最长 120 秒、正常每 30 秒续期；控制失效检测最多 5 秒，确认断联/健康过期后拒绝新打开；检测前窗口单列。旧流到期后最多 5 秒关闭，不能扩大旧授权范围 |
| AUTH-15 | 重启、超期休眠、墙钟回拨、配置回滚和旧代事件 | 不延长租约或恢复撤销版本，过期后直接/中继均不可用；时间不可信时失败关闭 |
| AUTH-16 | 重复 operationId、不同参数、调用超时/IPC 丢响应 | 同参数返回原结果，异参数拒绝；查询原操作不重复创建授权/设备；保留结果不少于 24 小时，容量满拒绝新修改而非提前丢弃承诺记录 |
| AUTH-17 | 重复 JSON 键、非法编码、超长/深数据、并发洪泛和慢订阅 | manifest 48 KiB、独立策略 8 KiB、深度 16、控制帧 64 KiB 等硬限生效；包装后另测帧大小；慢消费者有界处理，其他授权应用仍有基本可用性 |
| AUTH-18 | 原始异常含模拟秘密，读取本地存储并导出诊断/崩溃包 | 未授权主体不能读取秘密；普通错误、命令行/导出不含 token、邀请、私钥或正文；敏感材料不进入仓库/发行包 |
| AUTH-19 | 证书到期、正常轮换、旧钥泄漏撤销；中继观察受保护测试流量 | 不静默替换信任或忽略到期；私钥不交中继，在声明边界可证明被动中继不能还原正文 |
| AUTH-20 | 更新签名/摘要错误、降级、失败回滚 | 安全拒绝或恢复原允许版本，不丢失撤销版本，不自动重放业务写操作 |
| AUTH-21 | 子进程启动失败、崩溃、停止和升级清理 | 只回收持有句柄或完整核验归属的资源；无孤儿进程或未知服务被误停，用户停止抑制重启 |

## 7. 观测、计数和可解释性

| ID | 负载与操作 | 通过标准 |
|---|---|---|
| OBS-01 | 并行的不同应用、设备、服务与混合直接/中继流 | 可以按 app/service/device 与运行代次归因；聚合等于组成项，标识不包含凭据 |
| OBS-02 | 重复累计样本、乱序样本、旧代末尾样本、进程异常退出 | 不双计、不倒退；异常结束标明统计完整性，未知尾部字节不补造；重启代次不会错误相减 |
| OBS-03 | 至少 100,000 次短 TCP/HTTP 流跨过 8,192 条边界，叠加长期 WSS | 活动表和已关闭流归档有界；统计完整、不会达到固定总流数后永久失效；按窗口查询和累计汇总一致 |
| OBS-04 | 两端所有测试流正常关闭并等待采样排空，读取同一业务窗口 | 访问端 direct/relay Tx 分别对应发布端同路径 Rx，反向亦然，四项差均为零；窗口/异常不完整则禁止精确相等结论 |
| OBS-05 | ECS 独立计数与无业务基线，完整包围每轮业务窗口 | 零采集丢包/解析遗漏，记录时钟方法和前后缓冲。IP/TCP/业务字节分开；控制、TLS、ACK、重传等差异可解释；不把业务直连比例等同账单节省 |

限速、压缩、TLS 终止和应用代理可能改变计数层级；在测试前固定计数位置，不比较不同层的精确字节。UID 流量包含回环与原生进程开销，不直接当公网流量。服务端端口或接口不止一项时，应完整列出计数范围；不能只看一个端口就判断整个产品的中继消耗。

## 8. 生命周期、恢复与资源稳定性

| ID | 操作 | 通过标准 |
|---|---|---|
| OP-01 | 重复启动两个 UI、CLI、SDK 请求，同一用户重复运行网关 | 单实例/会话协调符合 SPEC，不重复占端口或误停另一实例；独立角色不相互覆盖配置 |
| OP-02 | 关闭 UI、正常停止、用户停止后出现网络恢复或延迟回调 | 关闭 UI 与停止网关语义一致且可理解；显式停止抑制后台重启；迟到事件不重开连接 |
| OP-03 | 原生运行时崩溃、父进程退出、初始化失败及子进程启动竞态 | 只回收持有的进程/Job；不留孤儿，其他网关/服务不受影响；重启受预算与退避限制 |
| OP-04 | Windows 锁屏、休眠/唤醒、用户登录退出，另测配置的后台运行模式 | 可恢复或明确显示不可用原因；不能声称电脑睡眠/关机仍能执行业务；不改变用户未授权的登录任务 |
| OP-05 | Android 页面退出、系统回收、前台通知停止、系统强行停止 | 行为符合平台与声明；用户强行停止后需用户重新启用时明确说明，不能宣称服务自动复活；通知和 SDK 状态一致 |
| OP-06 | 16 服务并发、多个应用反复注册/撤销，一项后端健康检查持续失败；各调用者超过 64 控制请求/128 数据流、Agent 超过 1,024 流 | 故障隔离，不阻塞无关服务；连接数、缓冲、队列、重试均有界；压力超限返回 RESOURCE_EXHAUSTED，不无限排队 |
| OP-07 | 24 小时混合负载后再做 72 小时；持续 WSS、周期短流、文件流与空闲交替 | 无崩溃、死锁、数据损坏、孤儿进程或无界增长；资源符合下述冻结预算，所有退出/取消可完成 |
| OP-08 | v1 配置迁移、重复迁移、迁移中断电/杀进程、旧版读新配置 | 原子性可证明；成功一次或保留旧状态；不丢失身份/授权；旧版本明确拒绝不兼容而非重置成宽权限 |
| OP-09 | 备份/恢复、磁盘满、存储拒绝、密钥存储不可用 | 保持失败关闭，不回落到公共凭据/不受限配置；原可用配置未被部分写破坏，恢复路径明确 |

资源测试必须在固定机器、负载与采样工具上每分钟记录一次。初始建议的发布验收预算为：预热 1 小时后，最后一小时的空闲后 RSS 中位数较首个稳定小时增加不超过 32 MiB；句柄/FD/线程在同一空闲检查点不超过基线的 5% 或 16 个（取较大者）；活动连接、关闭流归档和事件队列不突破各自配置上限。RSS 的 GC/缓存波动需使用同负载下的多次空闲检查点判断，不能靠重启网关通过。CPU/吞吐没有通用绝对门槛，应在 0.4 前用支持设备样本冻结每个平台的空闲 CPU、持续负载 CPU、峰值内存与吞吐基线及允许退化；未冻结预算时该项为阻断状态，不填写虚构性能达标。
