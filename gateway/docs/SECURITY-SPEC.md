# LinkGate 安全与身份规格

文档版本：1（草案）。日期：2026-10-29。目标版本：LinkGate 1.0。规范性状态：待实现与验收，不描述 0.2.3 已具有这些能力。

本文与 [工程规格](SPEC.md)、[产品方案](PRODUCT-PLAN.md)、[验收规格](ACCEPTANCE.md) 配套。MUST 表示发布门槛，SHOULD 表示偏离时必须在设计记录中说明理由并补充测试，MAY 表示可选能力。下文使用“必须／不得／应／可以”表达相同级别。

## 1. 范围、已有基础与发布边界

目标是一个所有者管理多个受信任设备、授权多个应用访问特定服务。Windows 提供发布和访问角色；Android 首版提供访问角色。公开不受信任多租户、任意目的地代理、远程 shell、出口节点、整机 VPN 不属于本规格。

0.2.3 已有严格配置解析、私有目录权限、运行时固定哈希、进程所有权、父进程死亡回收及脱敏计数。这些是保留的基础。当前配对文件仍共享 FRP 注册 token 和服务 secret，Android 服务未提供跨应用控制入口；当前控制 TLS 和 `useEncryption` 不能被表述为下面的逐设备授权和经验证的应用端到端安全。

已有实现依据：[服务器边界](../server/README.md)、[Windows 私有存储](../windows/LinkGate/PrivateStore.cs)、[配置合同](../windows/LinkGate/Profile.cs)、[Android 服务声明](../android/app/src/main/AndroidManifest.xml)、[配对生成器](../tools/create-profile.py)。正式验收必须同时检查设计和对应运行代码，不能通过修改产品文案宣布能力完成。

安全契约从 0.3 起约束新增接口。0.3／0.4 可使用明确标记的单所有者开发配置，但不得对外宣布可用于不受信任应用或独立设备撤销。身份、服务端授权、会话租约和安全更新的门槛在 0.5 实现，在 1.0 发布前全部通过。

## 2. 信任边界与威胁模型

需要保护设备私钥、配对凭据、应用授权、业务正文、目标服务身份及运行配置。业务应用只得到本次被授权连接，不得到网关全量配置或 FRP 注册能力。

| 对手或故障 | 必须覆盖的行为 | 本版边界 |
|---|---|---|
| 公网窃听、篡改、重放 | 验证服务端与设备身份；拒绝重放与降级；保护业务通道 | 不以可达性或来源 IP 代替身份 |
| 同设备上未授权 Android 应用 | 拒绝管理和受控数据通道访问，不泄漏服务目录或凭据 | 基于 Android UID、签名身份及用户授权；root／系统已被攻陷不在边界内 |
| 同 Windows 用户的其他进程 | 管理接口限制为当前用户；合作应用按能力授权；不无意导出密钥 | 相同用户下的恶意代码、进程注入和调试不被视为可靠可隔离的应用边界 |
| 已配对但已撤销的设备 | 拒绝新会话，并有界关闭存量会话 | 无网络时不能保证瞬时送达撤销；依靠有界租约失效 |
| 被盗的邀请或旧配置 | 短时、一次性、确认设备身份；已消费邀请不得重用 | 邀请有效期间的窃取仍需要所有者发现并拒绝错误配对 |
| 错误或恶意服务声明 | 不形成任意网络目标、shell、文件读取或全局代理能力 | 首版只发布所有者批准的固定本机回环 TCP 服务 |
| 失控运行时、崩溃、迟到事件 | 仅回收本次持有的进程；旧代事件不得污染新会话 | 不按名称或端口杀未知进程 |
| 控制／中继服务器被动读取流量 | 业务端到端通道保护正文；承认必要元数据可见 | 不承诺隐藏设备在线时间、地址候选、服务访问与字节量 |

控制服务器负责目录、授权分发和撤销，是可用性与授权执行的受信任组件。它不得通过目录更新静默替换已确认的设备公钥。传输保密不等于控制服务器不能拒绝服务、隐瞒撤销或提供错误元数据；完整服务器失陷的后果需在最终设计中单列。

## 3. 身份和数据分类

身份不得使用显示名称或端口作为主键。重命名设备、应用标签或服务标签不得改变其授权对象。

| 对象 | 内容与持有方 | 导出与使用限制 |
|---|---|---|
| 应用 manifest | `applicationId`、服务声明、协议、健康检查、连接策略；由应用提供 | 公开描述，不含 token、私钥或服务 secret；导入不等于授权 |
| 本机应用主体 | 平台核验的调用身份与注册记录，由 Broker 维护 | 不接受请求体中的包名、用户名或路径作为唯一身份证据 |
| 设备身份 | 不可猜测设备 ID、设备公钥及本机私钥引用 | 私钥在所属设备生成并保存，不因配对复制到别的设备 |
| 所有者信任 | 已批准设备公钥／指纹、控制服务信任及信任版本 | 变更有用户确认与审计，不由 manifest 覆盖 |
| grant | 应用、访问设备、目标设备、服务、操作、有效期及撤销版本 | 按最小范围授权；不能用一个 grant 枚举所有设备或访问所有服务 |
| 派生 FRP 运行材料 | 已批准目标的代理名、受限凭据和运行配置，由网关生成 | 只交给被持有、已核验的运行时；不交给业务 SDK 或诊断导出 |
| 会话授权租约 | 绑定身份与服务范围的短时会话资格 | 不能作为无限期通用注册 token；流不能越过授权范围 |

显示给用户的配对／授权界面必须显示可理解的应用、设备和服务名称，同时保留可核对的稳定身份。服务显示名相同不产生等价授权。

公开 manifest 的规范字段是 `applicationId`；内部对象模型使用 `appId` 表示应用主体或其别名。二者均不是调用者身份的自证，必须与平台核验的注册主体绑定，不因内部别名而在 manifest 中接受另一套字段。

## 4. 本机控制接口

### 4.1 公共要求

默认不新增 localhost 管理 HTTP 服务或公网管理端口。所有管理调用都必须由 Broker 从实际 IPC 连接获取调用主体。`app.register` 只登记描述与能力需求，不能自行获得授权。

应用注册、授权申请、状态读取与连接建立分别校验权限。查询接口必须过滤到调用者可见的范围，不通过错误、事件或列表泄漏其他应用的服务和设备。未授权和不存在的远端服务对普通应用应返回一致的不可用分类；管理员可读取脱敏原因。

Windows的[显式待确认申请实验](adr/0012-pending-grant-requests.md)中，applicationRef按实际调用范围校验，alias必须存在于已审核import；设备/发布者/服务引用只是未认证文字。保存申请和pending状态不授予任何网络能力，不能借此绕过设备身份、后端授权或撤销门槛。

新增独立的[Windows安全直连预览](adr/0013-secure-direct-streams.md)已实现本地CSR/所有者签发、双向TLS设备证明、发布端设备/应用/服务grant、一次性私有数据附接及活动撤销。它要求已知可达IPv4，只在显式配置的`secure.stream.direct`实验入口启用，旧待确认申请不自动授权。证书最长30天、控制与数据分离、每秒心跳、最长120秒单调租约和批量撤销检查均由Agent执行。软件密钥不是硬件证明；此证据不覆盖FRP/NAT/中继、Android、备份回滚、正式签名或完整配对运维。验收范围和限制见[当前进度](PROGRESS.md)。

`grant.request` 可以触发一次受限的用户授权流程，但不得自动批准。授权界面由 LinkGate 自己的可信 UI 显示，不使用第三方 Intent 中提供的应用名称或图标作为真实身份。拒绝后应有冷却和有界提醒，不能持续抢占前台。设备配对批准、设备撤销、其他应用授权管理及 `gateway.stop` 属于管理员能力；普通 SDK 可按范围查询授权、撤销自己的 grant 和关闭自己的连接，不能管理其他应用或停止整个网关。

RPC 使用 API 1 与主规格中的严格 JSON 合同。`requestId` 为单次请求 UUID；改变授权或设备状态的操作另有稳定 `operationId`。重复操作只返回原结果；同一 `operationId` 携带不同参数必须拒绝。超时或 IPC 中断后查询 `operation.status`，不得把未知结果当成失败再生成新的操作 ID。SDK 不得自动重放业务写请求。

### 4.2 Windows

Broker 使用本用户的 Named Pipe，设置明确的 DACL，只允许当前用户和部署所需的 SYSTEM；拒绝其他用户与远程管道连接。服务名称必须包含不可混淆的用户／实例范围，并在连接时核验实际对端，避免连接到预先占位的伪 Broker。

Broker 从操作系统获取管道客户端主体；可以结合客户端进程句柄、创建时间、已安装包身份和签名做注册核对，但不能仅凭应用传来的 PID、EXE 路径或 `appId` 授权。使用进程元数据时，必须用持有句柄避免 PID 重用竞态。

**Windows v1 的可靠隔离边界是用户，而非所有相同用户下的任意桌面 EXE。** Named Pipe ACL 和 DPAPI 不保证阻止恶意同用户进程；应用 grant 和短时能力主要约束正常合作应用。若将来要求强应用隔离，必须另行设计包身份／沙箱与数据通道边界，不能以路径或文件签名检查宣称已经解决。客户端与文档都必须显示这个差别。

### 4.3 Android

新增专用 Binder Broker，不直接导出现有前台运行服务的控制逻辑。入口取得 `Binder.getCallingUid()`，由 PackageManager 核对 UID 对应包、签名证书与获准签名 lineage，再匹配用户批准的应用注册。调用者自报包名只作请求参数，不构成身份。

首版不得以“与 LinkGate 同签名”作为全部第三方应用的必要条件；同签名权限只能用于内部组件。任意第三方应用接入必须有用户授权与稳定的调用者身份绑定。对于 shared UID 或一个 UID 对应多个包，必须核验完整身份集合，不声称能在共享 UID 内强隔离；身份集合变化时重新评估授权。

签名或安装身份变化、卸载重装、工作资料／多用户切换必须使不再匹配的注册失效。应用更新仅在签名连续性和身份检查通过时保留 grant。组件启停不得绕过 Android 前台启动限制或偷偷修改 Clash 的应用范围。

## 5. 数据入口与本机授权

### 5.1 兼容端口模式

兼容模式可在回环地址开放本地 TCP 入口，但必须标注它不提供逐应用隔离。任何能访问该回环入口的本机程序都可能发起业务连接，因此目标服务仍必须保留自身认证、HTTPS／WSS 和权限检查。不得把服务映射成公网通配监听，也不接受目标主机、端口或 URL 的任意运行时覆盖。

连接策略、是否启用中继和流量限制属于批准的服务配置。恶意应用不得通过更换连接参数扩大目标范围或放宽 `direct-only` 策略。实际业务认证材料不作为网关配对凭据复用。

### 5.2 受控 SDK 模式

受控模式不得仅从 Binder／Named Pipe 返回一个裸本地端口后就声称具有应用隔离。Broker 必须把已授权的私有 stream／FD／pipe 通道交给实际调用主体，或使用经过独立验证的等效数据能力机制。Android 可通过 Binder 传递私有 FD；Windows 使用与已认证 IPC 关联的私有句柄／管道。具体 framing 与句柄交付格式由工程规格固定。

能力绑定调用主体、注册代次、目标设备、服务、连接和有效期；关闭、撤销、主体变化或 Broker 代次变化后失效。短时能力不能从一个客户端复制到另一个客户端来获得不同目标。跨平台 raw TCP、HTTP 和 WebSocket 业务应使用同一授权决策，不各自引入旁路入口。

本机应用可能主动把自己获准的连接转交其他程序；网关不承诺解决已授权应用自行代理或外泄数据。Android root／Windows 同用户恶意进程的边界沿用第 2、4 节，不因私有句柄而扩大安全承诺。

## 6. 设备配对与授权生命周期

### 6.1 一次性邀请

配对必须使用系统 CSPRNG 产生至少 192 bit 不可预测的一次性邀请秘密，有效期不超过 5 分钟。二维码／文件只能携带配对所需的最小数据和短时秘密，不带所有者私钥、长期共享注册 token 或其他服务的 secret。不得把邀请秘密放进普通诊断日志、错误文本或可被不必要第三方接收的 URL 查询参数。

短数字码可以作为比较或带额外认证的查找提示，不能单独替代高熵邀请秘密。邀请的并发消费必须原子化；成功、用户拒绝、到期或主动取消后不得重新使用。失败尝试有速率限制，且错误响应不泄漏是否存在其他设备。

`device.pair.begin` 只创建有界待确认邀请。新设备生成自己的私钥，并通过成熟 TLS／mTLS 实现证明持有对应密钥。首次批准界面必须绑定所有者、邀请、实际新设备公钥指纹和设备名称，不能批准一个名称后任意替换公钥。`device.pair.approve` 必须来自有管理员能力的可信 UI／CLI，不向普通应用 grant 开放。

邀请是引导材料，不是设备身份。配对成功后生成独立设备记录与最小初始权限，邀请秘密应从内存和可清理存储中删除。配对重试沿用原操作状态，不重复创建设备或扩大权限。

### 6.2 Grant 与服务发布

设备配对不自动授权所有应用访问所有服务。`grant.request` 请求明确的设备、服务及访问操作，用户批准后才形成 grant。应用能请求更长的等待预算，但不能超出所有者设置的权限、时间和中继策略上限。

`service.publish` 只能注册 manifest 中经本机所有者批准的固定本机回环服务。不得发布任意内网地址、任意公网 URL、系统管理管道、文件路径或执行命令。代理名称和服务 ID 由 Broker 规范化派生，不允许应用冒用另一个设备／服务命名空间。服务端和发布端都要确认该设备拥有发布权限；仅在客户端 UI 隐藏按钮不算授权执行。

`service.unpublish` 应立即拒绝新连接，并按主规格明确已有连接是有界排空还是立即关闭。管理员安全撤销必须立即关闭已获知的对应活动连接，不得以普通排空策略绕过撤销。

### 6.3 撤销和网络分区

grant 和设备的撤销版本单调增长，不因进程重启、配置回滚或墙钟回拨而减少。设备撤销同时阻止它发布、访问和更新授权，并停止其关联的活动会话。服务端不能接受撤销前凭据重新注册为活动设备。

目标 v1 采用以下硬边界：

| 项目 | 上限与行为 |
|---|---|
| 已授权设备／应用／服务会话租约 | 最长 120 秒，不能由客户端自行延长 |
| 正常续租 | 正常情况下每 30 秒续租一次；失败可有界退避重试，但保留既有到期时间，不伪造续租成功 |
| 权威端已确认撤销，双方在线 | 立即拒绝新连接，5 秒内关闭对应活动会话 |
| 撤销通知不能到达 | 现有会话最迟在已持有租约到期后关闭；允许最多 5 秒调度余量 |
| 权威端不可达时的新会话 | 确认控制断联、健康信息超过 5 秒或网络代次改变后拒绝新 `connection.open`；首版不提供主动离线新建会话模式 |

租约针对被授权的设备／应用／服务会话或通道，多个同范围子流可复用仍有效的会话；不是每个业务包或 TCP 流都向云端申请授权。新租约和范围扩展需要服务器批准；已有租约的子流检查受认证控制通道同步的最新已知授权、健康及本机撤销状态。每设备控制健康探测的失效检测上限 5 秒；确认断联/健康过期后不得新打开。必须承认网络分区检测前最多 5 秒可在旧有效租约下准入子流，不能承诺物理断网瞬间的全局拒绝。新子流不得越过范围或到期时间；已知撤销时不能等满 120 秒。

接收端用单调时钟计算到期，过期必须同时关闭直接和中继路径。进程重启、休眠超出时限、网络代次变化或时间不可信时，不得用旧本地文件给租约额外续命。控制面断连可能使 P2P 会话在租约到期时关闭，这是首版有界撤销和可用性的明确取舍；不能宣传为完全独立于控制服务器的离线运行。

撤销 RPC 的结果必须区分“已记录撤销”“在线端已确认关闭”和“离线端等待到期”，并向管理员报告完成边界。若底层无法关闭对应活动流，就不能返回已完成的撤销结果。

## 7. 传输身份、加密与后端执行门槛

控制连接必须校验服务器身份、证书链／固定信任和有效期；不得接受任意证书或认证失败后自动退回明文。新增设备间数据保护必须使用成熟 TLS／mTLS 实现及平台／成熟库的密钥管理，不设计自有密码套件、nonce 或密钥交换协议。

设备间通道必须把双方已批准设备公钥身份与实际握手绑定，再绑定当前允许的会话范围。直接路径和经中继的路径具有相同的目标身份要求；换路径不能把设备身份检查降成只检查 FRP 共享 secret。已经确认的公钥变更需要明确的重配对或安全轮换，不信任服务目录的静默替换。

原应用的 HTTPS／WSS、Host、证书身份与业务认证继续保留。网关通道的加密不是关闭原应用校验的理由。若目标 v1 宣称中继无法读取正文，必须在实际数据路径中证明端到端握手在两台网关终止、私钥不交给中继、被动中继不能恢复明文，并明确第 2 节的控制服务器信任边界。

**当前 FRP 共享注册 token 与 `useEncryption=true` 不足以证明目标已完成。** 0.3 开始应验证固定 FRP 后端是否能通过受支持的服务端认证／授权扩展实现：

1. 设备独立凭据与角色限制；注册方不能发布他人的代理名。
2. 按服务与对端检查访问授权、授权版本与到期，而非只在客户端执行。
3. 正确处理撤销后的新工作连接、既有中继连接和已建立的直接通道。
4. 给不同服务正确归因并限制授权，不通过字符串命名约定形成旁路。

该项是 P0 设计门槛。若上游插件或当前适配层不能完整覆盖上述路径，必须给出明确的后端扩展、协议调整或替换方案及工作量；不得用统一 token 加管理 UI 冒充逐设备可撤销授权，也不得在此门槛失败时发布“成熟安全版”。不要求为解决此问题现在重写整个网络栈。

## 8. 重放、降级与请求安全

协议版本、授权范围及能力协商必须受认证保护。未知主要版本或缺少强制安全能力时明确拒绝，不能静默选择旧共享 token 模式。旧版 0.2.3 兼容配置仅在独立、显式标记的开发／迁移模式运行，不混入 v1 安全声明。

会话授权必须绑定签发者、接收设备／角色、设备密钥代次、应用主体、服务、授权版本、有效期和不可重复标识。具体编码与签名采用成熟库的标准格式，在实现设计冻结后提供测试向量；只验证字段文本而不验证认证和受众不得视为完成。

来自应用的 JSON 必须拒绝重复字段、未知强制字段、无效数值、超长／过深结构和非法编码。主规格中的消息大小、并发和速率限制为硬上限；安全实现可以在更小范围内拒绝，不能无限分配内存或把原始异常回显给应用。业务正文不作管理参数解析，不从业务输入生成 shell 命令或配置文本插值。

操作幂等记录必须落在受保护状态中，绑定调用主体、方法、规范化参数摘要与操作 ID。重复请求不能扩大授权；旧代晚到回复不能完成新代操作。SDK 将可重试的只读状态查询与未知结果的写操作区分，不自动重放文件写、支付、任务启动等业务行为。

## 9. 本地存储、轮换与迁移

公开 manifest、设备私钥、服务器信任、应用授权、派生运行配置和诊断分别存储。配置迁移以版本与原子事务管理，先验证再替换；无效导入不能破坏现有可运行身份。迁移前保存受保护恢复信息，但回滚程序不得恢复已撤销身份或降低授权版本。

Windows 使用本用户受限目录和平台保护保存秘密，拒绝不可信 reparse point／junction 替换。必须承认同一用户下的恶意进程不被 DPAPI 强隔离。Android 优先由 Keystore 保存不可导出设备私钥或包装密钥，其他敏感材料位于应用私有目录，禁用不受控备份和公开导出。不能因为文件被 Git 忽略就称其安全。

运行时 TOML 若必须含派生 secret，仅允许原生子进程所需的最小集合，使用受限临时／状态目录，不写命令行、环境全局变量或公共安装包。撤销、退出和升级后按所有权处理遗留文件；安全清理不保证对闪存作物理擦除，不作此类承诺。

证书和设备密钥轮换必须区分身份连续性与信任替换：提前告警、由旧有效身份认证新密钥、持久提交新版本后再切换，必要重叠期有界。旧钥泄漏时必须撤销而非无限延长重叠。过期凭据不能自动接受新信任来“修复连接”。所有到期检查均有可测试的时钟偏差边界；时钟明显不可信时拒绝敏感更新并返回可解释原因。

## 10. 限流、诊断和运行所有权

邀请创建、配对尝试、授权弹窗、枚举、连接数、未完成操作、事件订阅、日志和缓存都必须有可配置但有硬上限的预算。具体默认值以工程规格为准。对单个应用限流不能阻断其他已授权应用；紧急全局上限也必须返回稳定错误。不能从这些预算产生绕过授权的“临时可用”模式。

公开诊断仅包含稳定错误分类、对象的非秘密标识、计数、时间和状态。不得输出 bearer、配对邀请、设备私钥、FRP token、完整配置、URL 查询中的秘密、原始 SDP／候选及业务正文。IP 地址、完整目标域名和进程路径只在用户明确选择的本地受限排障包中按需要保留，默认导出脱敏。授权与撤销审计应记录主体、对象、结果和版本，但不保存完整密钥材料。

子进程启动前继续核验运行时摘要、来源和适用平台。Windows 保留 Job Object 及创建失败回收；Android 保留父进程死亡保护和代次隔离。停止和升级只操作本实例句柄或经 PID、创建时间、路径、归属完整核对的资源；不得按端口／进程名批量结束。用户停止优先于恢复循环，重试不能自动重放业务命令。

## 11. 更新、供应链与发布

1. 运行时和 FRP 补丁固定来源与版本，CI 从干净源码应用补丁、验证精确变更，再构建与回归。不得因下载失败悄悄替换为缺少安全适配的普通 frpc。
2. 发布清单包含应用、运行时、协议能力、配置 schema、最低安全版本、依赖／许可证与摘要。更新元数据有受信任发布签名，下载 HTTPS 不是签名替代。
3. Windows 安装包/可执行文件和 Android 更新身份采用稳定发布方案；Android 保留可验证签名连续性。安全软件告警通过核对来源与具体记录处理，不关闭保护或自动扩大排除。
4. 自动更新先下载、验证、准备恢复，再停止自有进程并提交；失败回滚到允许的兼容版本，但不得回滚安全撤销、信任或版本下限。用户业务写操作不得由升级器重放。
5. 当前仓库根许可证为 AGPL-3.0，FRP 为 Apache-2.0。SDK、独立进程调用与可分发组件的许可证策略必须在对外发布前明确记录，不默认全部为 Apache；本规格不构成法律解释。

## 12. 安全验收索引

测试必须使用独立测试身份和凭据，原始私钥不进入报告。正向成功与负向拒绝都需要实际运行证据；规范存在不算通过。

| ID | 必须覆盖的情形与通过条件 |
|---|---|
| SEC-01 | Windows 其他用户／远程 Named Pipe 客户端被拒；当前用户许可行为成立，并正确说明同用户边界 |
| SEC-02 | 伪 Broker 占位、PID 重用、请求体伪造用户名／包名／PID 不能替代实际 IPC 身份 |
| SEC-03 | 独立 Android UID 应用未经授权不能枚举、连接或管理服务；用户授予最小 grant 后对应操作成功 |
| SEC-04 | Android 签名不匹配、shared UID 身份集合改变、卸载重装／工作资料隔离按规定失效或重新确认 |
| SEC-05 | 普通应用不能批准自己、撤销其他应用、导出凭据或调用全局 `gateway.stop` |
| SEC-06 | 私有 SDK stream／FD 不经裸监听端口暴露；跨主体盗用 streamRef/附接票据被拒。已获准应用主动转交已打开 FD 或代理数据不在防委托保证内 |
| SEC-07 | 兼容端口模式保留业务认证，明确没有逐应用隔离，不出现意外公网监听 |
| SEC-08 | manifest 中注入任意目标、shell、文件路径、代理名或服务 ID 冒用均拒绝 |
| SEC-09 | 配对邀请高熵、5 分钟到期、取消、重复使用、并发消费和暴力尝试限制符合要求 |
| SEC-10 | 设备私钥不随邀请复制；批准绑定真实公钥；设备名相同或目录替换不能绕过密钥确认 |
| SEC-11 | 错误服务器证书、错误设备身份、降级与重放失败；认证失败不回退明文 |
| SEC-12 | 逐设备／角色／服务后端授权真实生效；一台设备不能注册或访问其他设备的服务 |
| SEC-13 | 在线 grant／设备撤销立即拒绝新连接、5 秒内关闭活动直连与中继会话 |
| SEC-14 | 分区最多 5 秒检测，确认断联/健康过期后不能新打开；旧会话到当前最多 120 秒租约边界加 5 秒余量内关闭，不扩大范围 |
| SEC-15 | 重启、休眠、时钟回拨、配置回滚与旧代事件不能延长过期租约或恢复撤销版本 |
| SEC-16 | 相同 `operationId` 返回同一结果；改变参数被拒；超时后查询状态不产生重复 grant／设备 |
| SEC-17 | 重复 JSON 键、超长／深消息、并发洪泛和慢订阅有界处理，不影响其他授权应用的基本可用性 |
| SEC-18 | 受限日志、普通导出、错误文本和命令行均不含配对秘密、token、私钥、业务正文 |
| SEC-19 | 证书到期、正常轮换与泄漏撤销可区分；旧信任不被静默替换；中继被动观察无法恢复被承诺保护的正文 |
| SEC-20 | 更新签名／摘要错误、降级、失败回滚均安全拒绝或恢复；不丢失撤销状态，不重放业务写操作 |
| SEC-21 | 崩溃／停止／升级只回收自有进程和临时资源，无孤儿进程、无其他服务被误停 |

各阶段的进入／退出条件由 [验收规格](ACCEPTANCE.md) 统一编排。任何 SEC-11、SEC-12、SEC-13、SEC-14 或私有数据通道边界未通过，都阻止宣称 v1 具有独立设备授权与撤销能力。发现底层执行能力缺口必须回到设计阶段，不以文档豁免替代实现。
