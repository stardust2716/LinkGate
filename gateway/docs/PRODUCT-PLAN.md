# LinkGate 产品与开发方案

日期：2026-10-29。方案修订：1。目标产品版本：1.0。状态：设计草案，尚未实施。

本文定义 LinkGate 从 0.2.3 实验网关演进为多应用接入产品的范围、用户流程、开发顺序和交付门槛。接口、对象及状态的规范定义见 [工程规格](SPEC.md)，信任与授权要求见 [安全规格](SECURITY-SPEC.md)，验证方法见 [验收规格](ACCEPTANCE.md)。实现与这些文件不一致时，不以本文的产品描述代替接口或安全要求。

## 1. 产品目标

LinkGate 为用户自己的电脑、手机和应用提供统一的私有服务连接能力。业务应用声明要发布或访问的服务，由网关负责设备配对、权限、路径准备、优先直连、中继回退、状态通知与流量诊断。

用户只需要安装和维护一套网关，不必为每个应用分别配置 FRP、STUN 和云端转接。应用开发者可以通过本地受控接口与薄 SDK 接入；已有 TCP 客户端在满足自身认证和端点适配条件时，也可使用本地端口兼容入口。

产品承诺是“在支持的网络条件下优先使用实际可用的直接通道，并按用户策略处理失败”，不是保证任意 NAT、VPN 和运营商都能直连。中继继续作为可选择、可观察、受预算约束的兜底路径。

### 1.1 首个成熟版范围

| 维度 | 1.0 必需范围 | 后续独立评估 |
|---|---|---|
| 用户与设备 | 一个所有者管理多个受信任设备与应用；逐应用、逐服务授权 | 公共多租户 SaaS、匿名分享、跨所有者协作 |
| 平台 | Windows x64；Android ARM64 | Linux、macOS、iOS、其他 CPU 架构 |
| 首批角色 | Windows 发布与访问；Android 访问 | Android 发布服务，须额外验证后台与服务端生命周期 |
| 业务协议 | TCP 字节流；其上的 HTTP/HTTPS、WebSocket/WSS | 应用原生 UDP、媒体专用数据报、系统组网 |
| 接入方式 | 受控 SDK；保留业务认证的本地 TCP 兼容入口 | 把完整运行时嵌入每个应用、浏览器免安装 P2P |
| 网络与出口 | IPv4、已认证的局域网候选优化、Windows 受控物理出口、Android 合规 VPN 共存 | IPv6 为显式选择的试验能力，双栈由专项验收决定，不提前宣称全覆盖 |
| 运维 | 单所有者自托管协调/中继、安装升级回滚、脱敏诊断 | 大规模跨地域调度、自动成本结算、企业运维平台 |

后续能力不得仅凭配置字段存在就列入支持表。能力表必须同时标明平台、发布/访问角色、网络条件、版本和验证记录。

### 1.2 暂停 ReDesk 接入实验

当前开发对象为 LinkGate。ReDesk 保持已有原生 P2P、助手 HTTPS、配对及服务，不为网关路线进行改造。已有 [ReDesk 接入评估方案](https://github.com/stardust2716/Redesk/blob/main/docs/linkgate-redesk-experiment.md) 保留为延期事项；其存在不表示接入正在进行。

## 2. 当前基线与真正缺口

当前可用基线为 0.2.3，仍是预览版。固定 FRP 后端已验证 TCP 直连及 STCP 回退，多端点 STUN 和 Windows TUN 物理 IPv4 绑定已纳入构建锁。Windows 具备自有 Job 进程管理，Android 有父进程死亡保护；两端提供脱敏的路径和累计业务字节统计。

2026-10-29 的四组内置测试完成 2,190 MiB 文件校验和 3,099 次 WebSocket 回显，发布端、访问端业务字节及 ECS 流量核对通过。三轮业务全直连，移动数据/Clash 关闭一轮为 90.06% 直连。完整证据见 [验收记录](../tests/NETWORK-RESULTS-v0.2.3.md)。

该结果来自一对实际设备与用户选择的四种场景，不能推导通用 NAT 成功率、长期可靠性或独立应用接入已完成。Android 请求由 LinkGate 自己的测试代码发起，尚未证明不同 UID 的外部应用已能安全、稳定地使用网关。

| 当前实现 | 成熟产品所缺能力 |
|---|---|
| 导入一份含全部服务秘密的配对 JSON | 应用声明、设备信任、授权和秘密分层；设备可撤销 |
| GUI/CLI 启停进程，固定本地端口 | 稳定本地 Broker、服务发现、授权连接、就绪通知 |
| 固定 1.5 秒回退及后台重试 | 明确的连接策略、准备预算和中继预算 |
| 统计进程内全部流量 | 按应用、设备、服务、连接与代次归因 |
| 有界测试期间的连接表 | 长期统计轮转、关闭流归档、准确去重及资源上限 |
| 启动时选择出口 | 网卡变化、切网、休眠唤醒、异常退出的有界恢复 |
| 私有构建和便携发布 | 稳定安装、签名更新、迁移、回滚和版本兼容 |

## 3. 用户流程

### 3.1 第一次使用

1. 用户安装 Windows 网关，并明确选择后台启动方式；普通业务不要求每次提权。
2. 部署向导连接用户自己的协调服务，验证身份与可达性。已有服务的导入先预检，不自动覆盖其他项目。
3. 手机安装网关，通过短时配对邀请与电脑确认建立信任；界面显示设备身份，不要求复制长期秘密到业务应用。
4. 用户添加或导入一个应用服务说明，确认发布目标、允许访问的设备及中继策略。
5. 用户批准业务应用的接入申请。应用获取已授权连接或兼容入口，等待对应就绪状态后开始业务。

“配对成功”“服务注册”“直接通道就绪”“实际直接业务”分别显示。配置完成但业务尚未访问时，不显示已经节省了流量。

### 3.2 日常使用

Windows 托盘和 Android 前台通知展示运行状态；关闭管理页面与停止网关有明确区别。用户可按服务暂停、撤销授权、查看真实路径和中继用量。业务应用可以知道网关未启动、设备离线、权限不足、正在准备、中继受限及网络变化，而不需要解析日志。

网络变化后，网关先判定旧通道是否仍有效，再按预算恢复。用户停止优先于自动恢复。业务应用负责自己的协议重连和写操作回执，网关不自动重放应用指令。

### 3.3 移除和恢复

用户能撤销单台设备、单个应用或单项服务，而不必重置全部设备。界面说明撤销对已建立连接的处理，并与安全规格一致。升级先验证签名、版本和配置可迁移性；失败回退到已知可用状态，保留可审计的结果。

## 4. 应用接入层次

### 4.1 兼容端口模式

适用于能配置 TCP 服务地址、已有业务认证的客户端。网关提供本地回环入口；应用按自身协议连接。应清楚显示入口属于哪个远端设备与服务，并处理端口冲突和失效。

回环监听不是应用隔离。其他本机程序可能访问裸 TCP 入口，因此该模式必须保留后端认证，不能用于承诺“只有指定应用可访问”。HTTPS/WSS 必须继续验证逻辑服务器身份；不能仅把域名换成 `127.0.0.1` 后关闭证书验证。

### 4.2 受控 SDK 模式

首批提供 .NET 和 Kotlin/Java SDK。SDK 负责发现网关、请求授权、发布/访问服务、等待就绪、订阅状态及释放连接。业务应用不获得 frps 注册 token、其他服务密钥或设备私钥。

受控模式通过经过授权的 Broker 交付私有连接通道，例如流或文件描述符；不能只在控制接口鉴权后返回一个公开监听端口，就宣称业务通道也已隔离。Windows 与 Android 的具体承载由工程和安全规格共同约束。

Flutter、Python 后续使用相同版本协议做薄封装。首版不为每个 SDK 再实现一套打洞，也不要求每个应用分别携带和升级 frpc。

### 4.3 不能自动套用的应用

固定公网地址且不能配置入口的客户端，需要适配。浏览器要受其安全模型、证书、跨域和本地网络访问条件约束。原生 UDP、实时媒体数据报和已有复杂 P2P 的程序，需要独立评估；不能通过增加 `protocol` 字段就实现兼容。

首个真实接入样例应选无成熟原生 P2P、当前确实经云转发大流量 TCP、能够保留认证与 TLS 的项目。ReDesk 不作为本阶段强制样例。

## 5. 技术与组织结构

```text
业务应用
  ├─ 薄 SDK ── 受认证本机 Broker ── 授权连接通道
  └─ 原有客户端 ── 本地兼容端口 ── 原业务认证
                              │
                       LinkGate Agent
             设备/应用/服务/授权/策略/统计/生命周期
                              │
                      传输引擎适配层
                              │
                固定 FRP 后端及受控补丁
                ├─ 直接通道 → 远端 Agent → 本机服务
                └─ 允许回退 → 自托管中继 → 远端 Agent

              协调服务负责注册、身份与策略相关控制
              STUN 负责候选地址发现，不转发应用正文
```

### 5.1 稳定的产品合同

业务应用只依赖 LinkGate 的版本化对象、操作、状态和错误码，不直接生成 FRP TOML，不解析原生日志，不依赖固定端口。服务 ID 与设备 ID 的逻辑身份保持稳定，运行时端口和后端进程可改变。

公开应用 manifest、设备私有状态、用户授权、派生运行配置必须分开。两端通过共同合同样本与一致性测试约束字段和迁移，避免 C#、Java 各自扩展成不兼容格式。详细定义以 [SPEC.md](SPEC.md) 为准。

### 5.2 保留 FRP，并隔离后端

首个成熟版沿用已验证的固定 FRP 后端，保持小而可审计的补丁。构建继续执行干净上游检出、补丁精确验证、测试、双平台构建及运行时锁，不能静默换回普通上游二进制。

连接状态、授权和 SDK 不直接依赖 FRP 内部数据结构。后续若实测发现 IPv6、原生 UDP 或弱网能力无法满足需求，可在同一组接入样例和验收条件下评估其他引擎。WireGuard、Tailscale/Headscale、自研 ICE 不作为首版并行实现目标。

### 5.3 身份与控制面不是后补功能

0.3 必须确定应用、设备、服务及授权的身份模型和信任边界，即使完整配对/撤销在 0.5 交付。共享注册 token 只能作为过渡部署模式，不能据此承诺逐设备隔离或公共多租户能力。

新控制面需要以服务端实际执行授权为准，不能只在客户端隐藏按钮。后端不能执行目标权限时，应返回不支持或阻止相关配置进入生产模式，不能假装已隔离。密码学、业务加密、撤销及本机攻击面的具体约束见 [SECURITY-SPEC.md](SECURITY-SPEC.md)。

## 6. 连接与资源策略

产品提供三种策略：快速连接、直连优先、仅直连。准备时间、允许回退、中继预算和失败行为由用户与服务策略共同决定。直接通道必须有实时可用证据，不能将 STUN ready 或历史 NAT 打洞事件改名成 DirectReady。

直连优先可在预算内预热后再交付业务通道；仅直连在不能建立时明确失败。已建立的中继 TCP/WebSocket 不保证迁移，SDK 可以通知应用按协议重建连接。写操作的幂等、取消和未知结果查询仍由业务应用负责。

中继额度应标明统计口径。业务明文字节不等于 ECS IP 字节或账单值。达到额度时对新连接和既有连接的动作必须预先定义并告知用户，不能静默截断文件或反复回退绕过预算。

有界恢复包括重试预算、退避、抖动、网络事件合并、旧代次隔离和用户停止锁存。统计应支持连接关闭归档、窗口轮转及累计值去重；不能长期依靠保存所有已结束连接来维持计数。

## 7. 开发里程碑与退出门槛

以下版本是目标里程碑，不是已经提供的接口承诺。版本按完成门槛推进，不以日期代替验证。

| 里程碑 | 主要交付 | 进入下一阶段的门槛 |
|---|---|---|
| 0.3 应用接入版 | 版本化合同、受认证本机 Broker、应用授权、服务描述、CLI、.NET/Kotlin 薄 SDK、独立应用样例、最低生命周期管理 | 不同 UID 的 Android 应用和独立 Windows 应用可接入；未授权调用被拒绝；兼容模式与受控模式安全边界可验证 |
| 0.4 连接可靠性版 | 三种连接策略、实时就绪、按服务诊断、网络变化恢复、统计轮转、中继预算、已认证的局域网候选优化；IPv6 专项研究 | 直接/回退/失败符合策略；切网与短连接压力验收通过；IPv4 必需能力与 IPv6 显式试验能力分开 |
| 0.5 设备管理与运维版 | 设备身份与短时配对、逐服务授权、撤销/轮换、服务端权限执行、证书生命周期、后台运行、迁移和回滚 | 丢失设备可撤销；权限在服务端有效；控制/数据加密边界验证；升级和恢复路径可复现 |
| 1.0 稳定发布版 | 安装与签名更新、部署向导、完整 SDK 文档和 skill、兼容性矩阵、长期测试与发布清单 | [ACCEPTANCE.md](ACCEPTANCE.md) 的必需项全部通过，无未关闭的发布阻断项；支持范围与已发布二进制一致 |

### 7.1 工作流与依赖

| 工作流 | 先决条件 | 可并行的交付 |
|---|---|---|
| 合同与 SDK | 对象/授权/错误/状态定义完成首轮评审 | 两端实现、示例应用、兼容测试、SDK 文档 |
| 本机安全 | 明确调用身份、授权持久化及私有连接边界 | Windows IPC 与 Android Binder 适配 |
| 连接后端 | 核心状态与代次模型稳定 | 直接就绪事件、策略映射、网络变化恢复、可达性诊断 |
| 设备控制面 | 身份、信任、授权和撤销语义冻结 | 服务端执行方案、配对界面、密钥存储、证书轮换 |
| 观测与运维 | 服务/应用标识和计数口径稳定 | 流量归因、脱敏导出、升级迁移、长时间压力测试 |
| 文档与发布 | 功能能力表及验证记录可读 | 用户指南、接入模板、skill、发布材料和回滚演练 |

可以并行开展不冲突的工作流，但不能先实现不安全的全量本机管理 HTTP API，再把身份和授权留作以后补丁。

### 7.2 明确的设计决策

| 决策 | 当前选择 | 重新评估的触发条件 |
|---|---|---|
| 产品边界 | 应用级私有服务网关 | 有真实需求和验收方法证明需系统组网 |
| 运行方式 | 独立 Agent 与薄 SDK | 有明确的无独立安装需求，且能承担嵌入后的升级、包体和 UID/VPN 责任 |
| 首版数据面 | 固定 FRP 后端与适配层 | 共同对照证据显示后端能力是主要瓶颈 |
| 业务接入 | TCP 兼容入口与受控 SDK 分开 | 其他协议完成独立设计、实现及跨平台验收 |
| 身份模型 | 单所有者、多设备、逐应用/服务授权 | 多所有者共享需要独立隔离和撤销规格 |
| 原生长连接 | 保持原路径或由应用显式重连 | 有完整业务语义和实测证明可实现透明恢复 |
| SDK 许可 | 发布前明确组件和依赖授权边界 | 不能从 FRP 的许可证推导 LinkGate SDK 自动采用同一许可证 |

## 8. 风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 只有内置 demo 成功 | 误以为外部应用已接入 | 将独立 UID/进程样例列为 0.3 硬门槛 |
| 本机端口被其他应用使用 | 越权访问远端业务 | 模式分级、后端认证、受控连接通道及负面授权测试 |
| 新身份模型未由后端执行 | 表面隔离、实际仍共享注册能力 | 服务端权限验证不通过则不能进入对应生产功能 |
| VPN/TUN、切网和 NAT 变化 | 错误路由、反复回退或连接中断 | 真实网络矩阵、有界恢复、明确配置要求和失败状态 |
| 额外网关降低性能 | 用户体验或耗电变差 | 固定业务条件对照，记录资源及冷/热启动，避免只报文件测速 |
| 长时间统计失真 | 用户无法判断中继成本 | 大量短连接、轮转、去重、重启代次和两端/云端核对 |
| 上游补丁与平台版本漂移 | 构建失效、安全修复难更新 | 固定来源、可重现补丁验证、升级独立回归、组件清单 |
| 把后台常驻等同于不可被杀 | 恢复承诺不成立 | 按 Android/Windows 实际系统规则运行并测试可解释恢复 |
| 过早扩展所有协议和平台 | 无法交付稳定核心 | 将未验证能力保持为明确的后续项，按验收门槛推进 |

## 9. 完成标准与发布交付

“成熟”需要可复现的支持边界和错误行为。除正常功能外，至少验证：两个独立应用接入、多服务并发、超过 8,192 次短连接仍准确统计；冷启动与预热分别记录；受限网络按预算回退或失败；切网、TUN 变化、休眠唤醒、进程崩溃和云服务重启；权限拒绝、撤销和证书错误；24 小时再到 72 小时稳定运行、资源受限和无孤儿进程。详细条件以验收规格为准。

发布交付包括：

- Windows 安装包/便携包、Android APK、服务端材料及签名/摘要信息。
- 用户安装、设备配对、服务配置、日常停止和恢复指南。
- 开发者合同、SDK 示例、错误码、连接策略和升级兼容说明。
- 参数化部署、只读预检、备份、迁移、健康验证及回滚工具。
- 固定上游、补丁、运行时清单、依赖/许可清单与升级维护说明。
- 脱敏的逐项验收记录及已知限制，不夹带个人配对或未提交的本机路径。

## 10. 后续 skill 的定位

skill 用于让其他 agent 按支持范围接入应用和验证结果，不代替未实现的 SDK、服务端授权或网络能力。建议按“应用适用性判断 → 协议和认证盘点 → 选择兼容/受控模式 → 生成无秘密服务说明 → 授权与接入 → 真实业务和失败验收 → 部署/回滚”组织。

skill 必须识别已有原生 P2P，保留原业务身份、TLS 和幂等语义，区分通道就绪与实际业务直连，明确浏览器、UDP、VPN 和平台限制。复用源码仓库的正式工具、参数和测试模板，不依赖 `private/` 或硬编码的 `artifacts/` 运维脚本。

当一种应用无法在合理成本内保持认证和协议语义，skill 应输出不适配原因及替代接入方向，而不是削弱校验以完成演示。只有通过真实接入验收的路径才加入支持清单。
